Authentication Strategies

Magic Links: Highly secure, no passwords to lose, but users must open their email. Best for B2B.
OAuth (Google/GitHub): 1-click friction, but requires developer console setup. Best for B2C.
Email/Password: Traditional, high friction, requires password reset flows.

VOL II · DEBUGGING

PART 28: Full-Stack Debugging

31. Trace the Entire Request

When a button fails in production, do not say "fix it". Trace the error to give AI the right context.

The 4-Layer Debugging Method

  • 1. Frontend (Browser Console): Did the React component crash before even sending data? Check F12 Console.
  • 2. Network (Browser Network Tab): Did the request fail? (e.g., CORS 403, Not Found 404). Check Payload & Response.
  • 3. Server (Vercel/Render Logs): Did the backend crash while processing? Check terminal or platform logs (Error 500).
  • 4. Database (Supabase Logs/RLS): Did the query get blocked by Row Level Security?

PART 30 & 31: Multi-Agent Workflows

33. Stop Asking One Agent to Do Everything

A single AI model cannot plan architecture, write React, configure Postgres, and audit security all in one prompt. You must route the tasks.

  • 1. The Architect (Reasoning Model): "Design this feature and wait for approval."
  • 2. The Builder (Fast/Coding Model): "Implement the approved plan exactly."
  • 3. The Reviewer (Independent Model): "Audit the builder's code before I deploy."
  • 4. The Debugger (Reasoning Model): "Trace this stack trace and find the root cause."
